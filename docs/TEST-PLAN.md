# خطة اختبار النظام — بيت المصور

الهدف: التأكد أن كل جزء يعمل كما هو مطلوب، بعدد كبير من الموظفين وبكل أنواع الحضور، قبل أي بيع. نفّذ بالترتيب، وسجّل لكل بند ✅ أو ❌ مع لقطة شاشة للأخطاء.

## 0) التجهيز (مرة واحدة)
| # | الأمر / الخطوة | المتوقع |
|---|---|---|
| 0.1 | ضبط البريد في `apps/api/.env` (SMTP_*) ثم `npm run api` | لا يظهر `SMTP not configured` |
| 0.2 | قاعدة نظيفة: `cd apps/api && npm run db:reset && cd ../.. && npm run api:setup` | جداول جديدة بلا بيانات |
| 0.3 | تشغيل: `npm run api` · `npm run web` · `cd apps/mobile && npm run lan` | الثلاثة تعمل |
| 0.4 | افتح الويب ← معالج التهيئة ← أنشئ المدير وأكّد OTP من **بريدك الحقيقي** | يصل البريد بتصميم الهوية |
| 0.5 | أضف فرعاً (من الخريطة) بوضعي GPS + شبكة المكتب (`192.168.0.0/16`) | يظهر في القائمة |
| 0.6 | بيانات جماعية: `npm run demo:data -w @attendance/api -- 100` | 100 موظف + حضور الفترة الحالية |

## 2) أنواع الحضور (الأهم)
جهّز موظفاً حقيقياً على الجوال (أنشئه من الويب، وكلمته المبدئية `12345678`).
| # | النوع | كيف تختبره | المتوقع |
|---|---|---|---|
| 2.1 | أول دخول | بريد + `12345678` | OTP بالبريد ← كلمة جديدة (8 خانات بحرف ورقم) ← دخول |
| 2.2 | حضور بالموقع GPS | داخل نطاق الفرع، اضغط «تسجيل الحضور» | تُسجَّل الحالة بلون المرحلة، ويظهر الوقت |
| 2.3 | خارج النطاق | من مكان بعيد | رسالة «لست داخل نطاق مقر العمل» |
| 2.4 | شبكة المكتب | عطّل GPS، وضع نطاق شبكتك في الفرع | يُقبل الحضور بالشبكة |
| 2.5 | موقع وهمي | تطبيق Fake GPS (Android) | يُرفض «موقع وهمي» |
| 2.6 | مرتين في اليوم | اضغط الحضور مرة ثانية | «سجّلت حضورك اليوم مسبقاً» |
| 2.7 | تأخر | غيّر حد الأخضر في الإعدادات إلى ما قبل الآن | مرحلة التأخر + الخصم في التقرير |
| 2.8 | بعد آخر مرحلة | اجعل آخر مرحلة تنتهي قبل الآن | «انتهى وقت التسجيل» ويُحسب غياباً |
| 2.9 | حضور المهمة | أنشئ مهمة لنفس الموظف اليوم **في موقعك** (قبل بدايتها بأقل من ساعة أو أثناءها) وسجّل بعيداً عن الفرع | يُقبل «في موقع المهمة»، والتأخير من بداية المهمة |
| 2.10 | مهمة بعيدة | اطلب الحضور بعيداً عن الفرع والمهمة | يُرفض |
| 2.11 | بصمة الجهاز | `API_URL=… DEVICE_KEY=bmk_… npm run demo:punches -w @attendance/api -- 50` | العدادات: حضور مسجّل / مكرر / غير مرتبط |
| 2.12 | إعادة الإرسال | شغّل 2.11 مرة ثانية | كلها `repeated`، بلا تكرار |
| 2.13 | تعديل يدوي | «الإجازات والأعذار» ← تسجيل حضور يدوي بسبب | يظهر في التقرير، والبصمة لا تستبدله |
| 2.14 | جهاز واحد | سجّل الدخول من جوال ثانٍ | يطلب OTP ثم يفك ارتباط الأول |
| 2.15 | إعادة ضبط الجهاز | من الويب «الجهاز» بسبب | الموظف يعيد التفعيل |
| 2.16 | بيانات الجوال مغلقة | حضور بلا GPS على شبكة المكتب | يعمل بالشبكة |
| 2.17 | تأكيد الهوية | فعّل البصمة/الوجه في «حسابي» | يطلبها عند الفتح والحضور |

## 3) قواعد الحساب (بالأرقام)
استخدم الموظفين التجريبيين (يظهر نمط كل واحد في اسمه).
| # | النمط | المتوقع في «التقارير» |
|---|---|---|
| 3.1 | PERFECT | بلا خصم، **مكافأة مستحقة** |
| 3.2 | LATE_REDEEMED | 3 أيام «معوَّض»، الخصم 0، بلا مكافأة (الإعداد الافتراضي) |
| 3.3 | LATE_END | خصم 3 × قيمة التأخر (لا أيام لاحقة للتعويض) |
| 3.4 | ABSENT_REDEEMED | الغياب معوَّض بخمسة أيام لاحقة |
| 3.5 | ABSENT_END | خصم **يوم كامل** = الراتب ÷ عدد أيام الفترة |
| 3.6 | EXCUSED | يوم «معفى»، بلا خصم، المكافأة مستحقة |
| 3.7 | ON_LEAVE | 5 أيام إجازة بلا خصم |
| 3.8 | NEW_HIRE | الأيام قبل المباشرة «خارج الخدمة» بلا غياب |
| 3.9 | HEAVY_LATE | خصومات كثيرة، بلا مكافأة |
| 3.10 | شهر الرواتب | الفترة من 25 إلى 24 وتُسمّى باسم شهر النهاية |
| 3.11 | تغيير السياسة | أضف مرحلة رابعة ولونها، احفظ | تظهر أعمدة وألوان جديدة في التقرير والجوال |
| 3.12 | مكافأة بسماح | اسمح بـ 3 أيام تأخر | موظف LATE_END يستحق المكافأة |
| 3.13 | إقفال الفترة قبل نهايتها | اضغط «إقفال الفترة» | نافذة هادئة تذكر تاريخ الانتهاء |
| 3.14 | موظف غادر | عطّل موظفاً (يُسجَّل آخر يوم تلقائياً) | يظهر في فترته الأخيرة فقط بأيامه الصحيحة |

## 8) تجربة الجوال (iPhone وAndroid)
- الأزرار بحجم مريح (44px+)، النص العربي من اليمين، لا يتداخل شيء مع النتوء أو شريط الأسفل.
- الدوران بين التبويبات الخمسة سلس، والسحب للتحديث يعمل.
- رسائل النظام تظهر كلها بنفس الشكل (أعلى الشاشة) وبالعربية.
- فصل الإنترنت: رسالة «تعذر الاتصال بالخادم» بدل دوران لا ينتهي.
- التاريخ ميلادي بأرقام لاتينية وبتوقيت الخادم.
