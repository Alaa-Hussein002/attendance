# خطة التحويل إلى منتج SaaS باشتراكات

> **مؤرشف:** أُلغي نموذج الاشتراكات والمتجر. النظام الآن لشركة واحدة (بيت المصور) بعدة فروع. هذا الملف محفوظ للتاريخ فقط.

## النموذج المقترح (حسب وصفك)
المشتري يشترك في **باقة** ← ينزّل النظام ويشغّله **محلياً على خادمه** ← **عند انتهاء الاشتراك يدفع للتجديد**. نسمّيه: *ترخيص باشتراك لنظام مستضاف ذاتياً*.

```
[بوابة البائع]  عميل ← يختار باقة ← يدفع ← تُصدر مفتاح ترخيص موقّع ← تنزيل المثبّت + المفتاح
[عند العميل]    النظام يتحقق من المفتاح محلياً (بلا إنترنت) ← حدود الباقة تُطبَّق ← إنذار قبل الانتهاء
[التجديد]       دفع ← مفتاح جديد يلصقه العميل (أو يتجدد تلقائياً لاحقاً)
```

## ما أُنجز الآن (المرحلة A) ✅
- **المفتاح:** سلسلة موقّعة (Ed25519). تعديل أي حرف يبطلها. البائع وحده يملك المفتاح الخاص.
- **الربط بالتثبيت:** المفتاح يُصدر لمعرّف تثبيت واحد، فلا يُشارَك بين عميلين.
- **الحدود حسب الباقة:** عدد الموظفين، عدد الفروع، الميزات (المهام، البصمة، واتساب).
- **حالات الاشتراك:** تجريبي 14 يوماً ← فعّال ← ينتهي قريباً (إنذار 14 يوماً) ← مهلة سماح 14 يوماً ← **وضع القراءة فقط**.
- **وضع القراءة فقط:** **الحضور لا يتوقف أبداً** (حتى لا يُظلم الموظفون)، ويبقى عرض البيانات. تتعطل: تصدير الرواتب، إقفال الفترة، إضافة موظفين/مهام/فروع، وتعديل الإعدادات حتى التجديد.
- **حماية الساعة:** تغيير تاريخ الجهاز للخلف لا يمدّد الاشتراك.
- **صفحة «الاشتراك»** للمدير + شريط تنبيه، وأدوات البائع: `license:keygen` و`license:issue`.

## المراحل القادمة
| المرحلة | المحتوى | ملاحظات |
|---|---|---|
| **B — بوابة البائع** | تطبيق ويب للبائع: العملاء، الباقات، الاشتراكات، الفواتير، الدفع الإلكتروني، إصدار المفتاح تلقائياً بعد الدفع، تذكير تجديد بالبريد، صفحة تنزيل للعميل | بوابات دفع سعودية مثل Moyasar / Tap / HyperPay (مدى وApple Pay وبطاقات) |
| **C — التغليف** | مثبّت بأمر واحد (Docker Compose: قاعدة بيانات + API + ويب)، نسخ احتياطي واستعادة، تحديثات بنسخة جديدة، فحص صحة | العميل لا يحتاج خبرة تقنية |
| **D — نسخة مستضافة (اختيارية)** | تشغيل عملاء على خادمك بدل خوادمهم | تحتاج مراجعة عزل بيانات الشركات وتكاليف استضافة ودعم |

## قرارات أحتاجها منك قبل المرحلة B
1. **الأسعار:** سعر كل باقة (شهري/سنوي) وهل التسعير بالباقات الثابتة أم بالموظف؟ (الحدود الحالية للتجربة: الأساسية 15 موظفاً/1 فرع، الأعمال 60/5، المؤسسات 500/50 — قابلة للتغيير).
2. **التوزيع:** هل تريد النظامين (محلي + مستضاف عندك) أم المحلي فقط في البداية؟
3. **الدفع:** البدء بتحويل بنكي/فاتورة يدوية ثم الدفع الإلكتروني لاحقاً، أم الدفع الإلكتروني من اليوم الأول؟
4. **التجربة والسماح:** 14 يوم تجربة و14 يوم سماح مناسبة؟ وهل تقبل سياسة «الحضور لا يتوقف أبداً» بعد الانتهاء؟
5. **الجانب النظامي (يلزم مختص):** الفوترة الإلكترونية (هيئة الزكاة والضريبة — فاتورة)، ضريبة القيمة المضافة 15%، السجل التجاري، عقد الخدمة وسياسة الخصوصية (نظام حماية البيانات الشخصية). لا أستطيع الجزم بالمتطلبات الدقيقة، فاسأل محاسباً/مستشاراً قانونياً.
6. **الدعم والتحديثات:** مستوى الدعم المشمول، وهل التحديثات مجانية طوال الاشتراك؟

## مخاطر يجب أن تعرفها
- النظام المحلي يتيح للعميل التلاعب بالكود نظرياً؛ الترخيص يحمي الاستخدام العادي لا القرصنة المتعمدة. للحماية الأقوى تُستضاف النسخة (المرحلة D) أو تُشفَّر الأجزاء الحساسة.
- **المفتاح الخاص للترخيص:** إن فُقد لا تستطيع إصدار مفاتيح، وإن تسرب يستطيع أي شخص إصدارها. احفظ نسخة غير متصلة بالإنترنت.
- **النسخ الاحتياطي:** مسؤولية العميل في النموذج المحلي؛ نقدّم أدوات لا ضماناً.
